# 触见桌面整合版

## 正式候选入口（2026-11-04）

候选版本为 **1.0.0rc1**，基于`b732414`整合版继续维护。版本与组件清单以[软件发行说明](../docs/SOFTWARE_RELEASE.md)和[release/software.json](../release/software.json)为准。默认Tang镜像包含完整板内启动校准，待真实测量通过后进入业务；旧表缺失只阻止`restore`路径，不阻止`startup`算法构建。候选尚待本轮声学校准与整机验收，桌面可独立离线运行和测试。

- `python -m desktop_app`：默认使用者界面，不连接设备。
- `python -m desktop_app --developer`：开发者工作台。
- `python -m desktop_app --demo`：使用模拟设备，不自动呈现。
- `powershell -File desktop_app/build_user_windows.ps1 -Python <python.exe>`：当前桌面便携包入口，产物为`dist/user/触见体验台.exe`及同目录便携ZIP。

正式Tang控制使用HAP3，静态相位发送要求设备声明`STATIC_PHASE`，校准表回读要求`CAL_READBACK`。MG24接收固件使用独立`MG24_RX1`协议；当前MG24有线采集／逐通道校准使用[独立工具](../firmware/xiao_mg24/README.md)，主界面尚无第二个MG24串口会话。主界面的采样控件依据当前控制设备是否声明`adc_capture=1`开放，不能把它当作已经集成MG24直连。

`startup`镜像上电先等待CAL2校准，普通HAP3界面此时还不能接管。使用独立校准工具连接Tang和MG24，完成测量、四步求解与复测；设备到达DONE并接受RELEASE后，再由桌面HAP3会话连接。默认启动条件为50 mm、测量等级20、参考通道0，需与实际测量位置及电气条件匹配。`restore`镜像只恢复经验证的旧值，不运行新校准；`uncalibrated`镜像没有板内启动校准求解，不能仅靠补入一张表就称它完成了新测量。

以下保留各日期的功能与验证记录；入口冲突时以前述候选入口为准。

## 2026-11-04 手姿与压力序列处理

已实现的数值处理包括：从21关节建立掌部正交坐标系、输出局部关节及几何弯曲特征；以整段压力的加权边界确定固定位置和比例，保留帧间移动；连续相位求解后尝试各通道相邻的64档相位码，只接受目标函数严格下降的修改。默认最多两遍离散精修，输出指标对应最终相位码，并单列连续解、量化基线与独立细网格误差。

压力窗口默认勾选“保持整段动作的位置与大小”，可导出手姿／压力分析和动作相位计划。计划由独立静态帧组成，默认最多24帧；界面均匀选取最多12帧，没有压力或接触的帧注明跳过。导出不发送、不启动，也不声称设备已实现连续压力动作播放。命令行示例：

```powershell
python -m desktop_app.pressure_sequence --output "analysis.json"
python -m desktop_app.pressure_sequence --output "phase-plan.json" --compile-frames 12 --z-mm 50
```

“导入序列”还可选择ContactPose单个抓握的`annotations.json`。它仅提供静态21关节姿态：没有压力热图、MANO网格或可播放动作，压力发送控件不开放。程序接口`load_contactpose(path, side="left", frame_index=0)`可明确左右手及原始帧；双手注释省略`side`时拒绝猜测。坐标保持原始米制物体坐标，移动手按官方`hTo`逆变换恢复；它没有注册到EgoPressure压力垫或本机阵列。

验证覆盖官方ContactPose注释、独立矩阵变换、掌坐标对刚体变换的不变性、固定映射下的接触位移和相位码实际目标函数。两份官方完整注释的9组帧／左右手检查，最大误差为`6.36×10⁻⁹ m`；自动测试保留一组来源明确的真实关节节选。ContactPose来源及许可见[模块说明](hand_datasets.py)；EgoPressure的[许可与来源](assets/egopressure/NOTICE.md)单独保留。

这些是公开数据的离线几何／压力处理与理论声场优化，不是实时手跟踪、临床角度测量或实测触觉增强。手绘掌面示意也仍是独立的参考图。

图形界面、真实样本下载和对照脚本见[手部数据工作流](../docs/HAND_DATA_WORKFLOW.md)。

### 构建 Windows 可执行程序

在 Windows 上使用 64 位 Python 3.10+，建议建立独立构建环境：

```powershell
python -m venv desktop_app/.runtime/build-venv
desktop_app/.runtime/build-venv/Scripts/python.exe -m pip install -r desktop_app/requirements-build.txt
powershell -NoProfile -ExecutionPolicy Bypass -File desktop_app/build_user_windows.ps1 -Python desktop_app/.runtime/build-venv/Scripts/python.exe
```

脚本使用 PyInstaller 生成文件夹便携程序，同时生成 ZIP 与 `build-info.json`（记录实际依赖版本及 EXE 的 SHA-256）。`dist/user/TouchSee-User/`是完整运行目录；打包脚本同时在`dist/user/`保留可执行文件和依赖。快捷方式须指向此次产物，不能继续使用其他工作树中的旧程序。只打包 TkAgg 图表后端；输出目录 `dist/` 和构建缓存 `build/` 均被 Git 忽略。打包版启动错误尝试写入 `%LOCALAPPDATA%\TouchSee\logs\startup-error.log`。

打包后可执行以下自检，运行可见 Demo 流程并自动关闭，不连接真实串口：

```powershell
Start-Process -FilePath 'desktop_app/dist/user/触见体验台.exe' -ArgumentList '--user-self-test desktop_app/.runtime/frozen-check' -WindowStyle Hidden -Wait
Get-Content desktop_app/.runtime/frozen-check/user-gui-smoke.json
```

自检覆盖绘图、尺寸与关系、保存导入、发送确认、播放、阵列切换和回传超时。报告中 `passed` 应为 `true`；截图写入指定目录。便携版验证使用 EXE 与 `_internal` 构成的独立目录，并从环境中移除开发用 Python 路径。这项自检使用模拟设备；实板验证以对应日期和配置记录为准。修改源码后需要重新构建，桌面快捷方式才会运行新版。

## 绘制与保存图形

1. 用“连续直线”依次点击画折线，点击起点闭合；右键或 Esc 完成。原来的点选连线已合并为这个工具，没有独立打点模式。位置不吸附网格，靠近已有端点时可连接。
2. 用“矩形”“圆”点击两处或拖动绘制，在同一画布组合图形。“控制点曲线”依次点击起点、两个控制点、终点，生成三次 Bézier 曲线；曲线不要求穿过控制点。
3. 选择后拖动端点调整位置、拖动直线改成圆弧、拖动曲线手柄塑形；“移动”平移元素。“擦除”或 Delete 删除整条线／整段圆弧／整条控制点曲线，支持撤销和重做。暂不提供交点间局部修剪。滚轮缩放、“适合窗口”只改变视图。
4. 点击“保存图形”选择名称和位置，文件保存为 `.json`。左侧显示当前文件名与是否有未保存的更改，底部提示完整保存位置。
5. 点击“导入图形”选择已保存的 `.json`，恢复图形与参数；文件选择窗口记住本次运行中上次使用的目录。也可用 `Ctrl+O` 导入、`Ctrl+S` 保存。
6. 导入、读取设备图形或关闭窗口时，若有未保存的修改，可先保存、放弃更改或取消。文件损坏不会覆盖当前草稿，保存失败不会覆盖原文件。

导入只改变电脑上的待发送图形，不会发送命令或启动设备。要播放，先停止当前输出，点击“发送到设备”，收到确认后再播放；即使导入内容与设备相同，也需要再次发送确认。

### 几何关系、尺寸与顺序

- 选择工具中，按住 Shift 选两个点，在“关系”页点“重合”；也可把一个端点拖到另一个点上。重合会持续保持，支持保存与撤销；同一条线的两端不能重合。
- 选择直线可设水平、竖直；Shift 多选两条直线可设平行、垂直。相切支持直线与圆、两个圆，以及共同端点处的直线／圆弧／控制点曲线。切点落在线段延长线上会拒绝；圆与控制点曲线的任意位置相切尚不支持。
- 不适用、已添加或求解冲突的关系按钮置灰；鼠标指向按钮可查看原因。取消关系：选择相关点／线条，打开“关系”页，选中列表中的一项，再点“移除选中的关系”。取消重合时，依赖该连接的相切关系也会移除；支持撤销。
- 双击选中整个轮廓，拖绿色手柄旋转，按住 Shift 按 15° 调整；也可在“尺寸”页输入旋转角度，正数逆时针、负数顺时针。矩形默认保持对边平行、邻边垂直，允许任意朝向。旋转保持尺寸，宽高标注方向随图形一起转动。手动水平／竖直关系或外部连接阻止旋转时会提示，不擅自删除关系；旧文件中的矩形方向关系可按上述方式移除。
- 单击选线，双击选整个轮廓。“尺寸”页显示对象名称、当前值和尺寸含义，只提供适用选项：直线长度、圆／圆弧半径与直径、曲线／整个轮廓的宽度和高度。矩形双击后可改整体宽高，图上显示已设标注。尺寸作为持续关系保存；整体倍数缩放以草图原点为中心，同时更新几何和已设尺寸，整体偏移与显示高度不变。冲突修改会拒绝，可在“关系”页移除关系后再编辑；不要求完全定义。
- 在“顺序”页选中轮廓后上移、下移；跳过排序采用稳定的创建顺序。新增／删除轮廓后恢复自动排序。开放线条也保留，不擅自补闭合边。
- 尽量避免闭合轮廓共边。按最终顺序减去已经呈现的重合部分，后续轮廓可能分成多段。直线、同圆圆弧和相同 Bézier 曲线的重合区间在离散前处理；交叉点不算公共线。独立段之间关闭输出再切换。
- “手掌预览”查看完整待发送图形，不发命令；播放位置来自设备回传，切换线段时隐藏触觉亮点。手掌仅为示意，不是位置检测。

### 手掌参考与绘图范围

画布以掌面为主要区域，背景保留完整手形，手指只显示当前视野内的部分。白色画布基本都可落点，包括靠近顶部和手掌外的位置；边缘仅保留少量留白。滚轮缩放视图时，图形和手同步缩放，缩小后自然露出更多手指；“适合窗口”恢复掌面与草图视野，均不修改实际坐标。

明显超出掌面时显示黄色提醒，不禁止发送、不弹确认框、不自动裁剪。当前提醒给掌面参考留出 10 mm 余量，检查整条曲线和整体偏移；手指与伸出的拇指不计入主要掌面。此余量只是界面提示规则，实际手掌较大的使用者可以忽略。设备声明的命令范围与容量仍需满足。

“放入掌面”由用户主动点击，将整张草图等比例缩小（不放大）并移到掌面中央，尺寸同步更新，可撤销。“整体缩放”改变图形实际大小，手掌参考不变，与滚轮缩放视图含义不同。

草图保留可编辑几何，电脑以 0.1 mm 几何离散阈值生成折线，最多 32 段、合计 256 个路径坐标；过于复杂的图形会要求简化，不静默截断。旧路径文件保留原 64 点限制。整数微米传输精度、路径容量与阵元数量均不代表触觉定位精度或辨识能力。

顶部图案按钮提供固定点、水平线、竖直线、圆、正方形、三角形和箭头，点击即可预览。“自定义”返回草图，切换预设不会丢失草图。

“水平偏移”“垂直偏移”平移整张图形，“显示高度”设置所在平面。左侧半径只影响预设图形，正方形使用半边长。新文件为 `haptics-config-3`，保存控制点、几何关系、尺寸、顺序及对应路径，并在导入时校验一致性。旧网格／点列文件可迁移，未经编辑时保留原播放语义。设备只回传编译后的路径，无法恢复未上传的原始几何关系；保存原草图文件可保留完整编辑能力。

## 连接与 Demo

1. 选择 Demo 并连接，在画布绘制一个三角形。
2. 点击“发送到设备”，自动打开“播放画面”。收到确认前，“播放”置灰；收到匹配的完整图形回传后，显示“图形发送成功，可以播放”。只连接设备或只收到命令应答不会解锁按钮。
3. 点击“播放”，亮点按模拟设备返回的位置移动，默认两秒一圈；暂停后保留橙色位置标记，停止后只保留轮廓。修改图形后需重新发送，断开或回传过期会隐藏位置并禁用播放。普通模式即可看到完整反馈；相位和理论声场仍在调试模式。
4. 停止并断开，在“设备设置”将 4×4 改为 8×8，重新连接、发送和播放。同一图形坐标不变，回读相位由 16 路变为 64 路。
5. 停止后选“设备本地控制”，通过调试模式的 Demo 按键切图与播放，观察回传变化。勾选“模拟回传中断”可验证超时。重连 Demo 会创建新的待机设备。

设备设置提供 4×4、6×6、8×8、12×12、16×16 及自定义 1～16 行列，默认阵元间距 10 mm。手动设置仅用于 Demo 和离线预测，真实设备尺寸由握手读取。

图形设计与阵列大小独立；使用所有实际阵元计算单焦点相位。发送前检查实际坐标是否在设备声明范围内、路径是否超过容量、阵列声明是否一致；超出范围不会自动裁剪或缩放。命令接受范围不等于已验证的触觉有效范围。

## 扫描路线与演示边界

当前FPGA按**单焦点沿完整轮廓高速循环扫描**执行。电脑一次提交完整图形，FPGA独立完成插值、相位求解和更新；不依赖电脑实时逐点发送。

Demo 只在取快照时计算当前位置和相位，没有高速硬件时序。运行时每 0.05 秒回传一次，其他状态每 0.5 秒回传一次；这是内存模拟传输，不代表真实串口支持相同数据量。播放画面的亮点使用最新收到的位置，不在电脑自行补算真实设备的运动。它默认慢速播放，不能用动画流畅度或通信成功证明人能辨认图形。实际扫描参数、手部移动影响和辨识率都需要样机实验；多焦点与手部跟踪仍为后续方向。

### 接收板调试（历史MCU直接采样入口）

连接后打开调试模式，在“实测数据 → 接收波形”点击“采集一次”或“连续查看（2 次/秒）”。旧固件不支持时采样按钮置灰；断线保留历史波形并标明来源和数据年龄，不继续伪装实时反馈。无需先发送或播放图形就可查看静态电压。

真实采样支持 [F411 固件及接线](../firmware/nucleo_f411re/README.md#41-接收板--nucleo)和 [F103C8 CubeIDE 工程](../firmware/stm32f103c8_cube/README.md#4-接收板与按键)：ADCV_P 接 MCU 的 PA0，共地，接收板单独供 5 V。F411 使用板载 ST-LINK 虚拟串口；F103 使用 PA2/PA3 外接 3.3 V USB-UART，两者当前为 115200、8N1。Demo 可演示待机噪声与播放波形，但不模拟真实声压。

每帧为 400 kS/s、200 个原始 ADC 点（0.5 ms），帧间不采样。页面计算直流、峰峰值、交流 RMS、40 kHz 峰值；默认 ADC 参考 3300 mV、分压还原倍数 3.4，可修改并重新计算。倍数只还原末级分压前的等效交流幅值，不会恢复前级削顶或提高有效分辨率。默认参考电压未经校准，结果不是声压、空间扫描图或完整图形的平均值。

“导出波形 CSV”保留原码、时间、来源、配置版本、窗口开始时运行状态和换算参数；真实来源为 `ADC_UNCALIBRATED`，Demo 为 `DEMO_SYNTHETIC`。此格式不同于空间扫描 CSV，不可用来冒充二维声场。

2026-10-04 起，每次通过序号、CRC、启动标识和来源校验的采样自动后台保存。“打开测量记录”进入本次连接的目录；源码版位于 `desktop_app/.runtime/receiver/`，EXE 版位于 `%LOCALAPPDATA%\TouchSee\measurements\`。`captures.jsonl` 逐条保存完整原码、采样启动时间、运行标志和最近的配置/相位回读；`summary.csv` 每个窗口一行，包含直流、峰峰值、RMS、40 kHz 峰值和 ADC 电源轨提示。重新连接另建目录，断线不删除记录；写入失败明确提示，串口采样仍可手动导出。

汇总默认使用 3300 mV 和 3.4 倍，并写明换算参数；界面修改参数仅影响当前波形和手动导出的 CSV。可从原码重新生成整份分析，保留原始记录：

```powershell
python -m desktop_app.receiver_log '测量记录目录或 captures.jsonl' --vref-mv 3280 --divider 3.4
```

生成 `analysis.csv`，可用 Excel、Python 或 MATLAB 比较多次窗口；JSONL 可直接提供给后续分析工具。`last_state_context` 为最近一次数字回读，记录其年龄和配置版本是否一致，不等同于采样瞬间的焦点或接收器位置。记录不包含人工移动接收器的实际坐标，不能自动拼成声场图。

`model.py` 使用各向同性单频点声源叠加，声速假设为 343 m/s，幅值按理想相干和归一化。显示载波输出时的相对分布，不按输出等级线性换算驱动电压；未模拟器件指向性、反射、调制包络或人体感知，数值不是 Pa、dB SPL 或触觉强度。

## 真实设备与协议

交接顺序、完整报文和验收模板见[上位机联调与验证计划](../上位机联调与验证计划.md)。

### BLE 蓝牙

选择“BLE 蓝牙”→“扫描设备”→选择你们的模块→“连接”。扫描可取消，设备须完成协议确认后才能发送图形，收到配置确认与状态回传后才能播放。蓝牙断线会隐藏位置并禁用播放，重连后需重新发送图形。

默认 NUS 服务是可替换的开发配置，在“连接设置”中按模块资料修改收发 UUID、写入方式及分包上限。BLE 不使用电脑端波特率；模块与 FPGA 之间若使用 UART，仍需另行匹配两端参数。此适配传输HAP3帧，不保证任意蓝牙模块可直接控制FPGA。详见 [BLE 对接说明](BLE.md)，含配置、带宽限制、映射待决事项和验证边界。

### 串口

界面示例：[常用及自定义波特率](docs/baud-options.png)。

切换“真实串口”，在顶部选择 COM 端口和波特率后连接，默认 115200 baud，需与板端一致。普通界面提供 1200、2400、4800、9600、19200、38400、57600、115200、230400、460800、500000、921600、1000000、1500000、2000000、3000000 等常用选项，也可直接输入其他正整数。下拉选项不代表适配器或 FPGA 支持全部速率；连接后需先断开再修改，Demo 不使用波特率。固件需实现 [HAP3 协议](PROTOCOL.md)，包含多段路径、跳转时关闭输出及对应状态回传；拒绝 HAP1／HAP2 固件，不自动回退为 Demo。固件须按串口带宽安排回传周期，低速率可能导致复杂图形的回传超时，不能照搬内存 Demo 的回传频率。

配置只能在电脑控制且待机时修改，板端控制来源只能在待机时切换。本地正在播放或暂停时可点击“电脑控制”：客户端先发 STOP，收到停止 ACK 和更新的 IDLE/输出关闭快照后再发 MODE；不会自动 START。停止失败、状态未确认或用户再次 STOP 时不继续切换。连接本身不接管本地运行；采样在 LOCAL/REMOTE 均可请求。发送成功不代表状态已确认：客户端等待 ACK 和后续完整 STATE。REMOTE 断开尝试发送 STOP，失联后的关闭依赖板端看门狗；LOCAL 断开保留独立运行。界面状态未知时不能确认硬件已停。

## 相位黄金向量（供 FPGA 逐通道比对）

`golden.py` 用 `model.py` 的参考模型批量导出相位码，供 RTL（Register Transfer Level，寄存器传输级）仿真对拍：

```powershell
python -m desktop_app.golden
python -m desktop_app.golden --array 8x8 --rate-hz 2000
python -m desktop_app.golden --file 图形.json --out desktop_app/exports/我的向量
```

默认导出完整一圈，输出到 `desktop_app/exports/golden-*/`：`*.csv` 是每帧的焦点坐标与全部相位码（人看），`*_phases.mem` 每行一帧、每通道两位十六进制（`$readmemh` 可直接读），`*_focus.mem` 是 32 位补码的焦点坐标，`*.json` 记录参数与 SHA-256 校验和。

导出内容是**设备期望值**，不是实测数据；更换阵列尺寸或修改图形后必须重新导出。
