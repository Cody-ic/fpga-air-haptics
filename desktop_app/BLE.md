# BLE 适配与待定接口

更新日期：2026-09-25。电脑端已实现 BLE 扫描、连接、分包发送和通知接收；测试使用假的 GATT 设备，尚无蓝牙模块、FPGA 板或驱动 PCB 的联调结果。**HAP3 仅为现有上位机和 Demo 的协议草案，未与板端共同定稿。**

## 1. 分层与分工

```text
图形编辑／播放界面
        ↕ 完整图形、控制命令、设备状态
Session + HAP3 草案（协议语义、校验、确认与回读）
        ↕ 原始字节流
串口 transport.py 或 BLE ble_transport.py
        ↕
待选蓝牙模块／FPGA 固件
```

BLE 是新增的传输方式，不负责生成扫描轨迹或相位。电脑提交完整图形，FPGA 自主扫描；串口与 BLE 同时只连接一种。[Android 原型](../mobile_app/README.md)已复用同一协议草案，支持触屏绘图、Demo、BLE 与状态回传，尚未完成实体手机和模块联调。

## 2. 电脑端操作

1. 开启电脑蓝牙，选择“BLE 蓝牙”，点击“扫描设备”。扫描约 5 秒，可取消，期间仍能编辑图形。
2. 根据名称与地址选择你们的模块；列表不自动选择最近的设备。未发现设备时检查供电、可发现状态、系统蓝牙权限及是否被其他客户端占用。
3. 点击“连接”。软件先连接蓝牙并订阅回传，再等待设备完成协议确认；扫描到或蓝牙连接成功都不等于 FPGA 已可控制。
4. 设备报告实际阵列和状态后，发送图形。收到配置 ACK 和后续匹配 STATE 才能播放，手掌画面的位置来自 STATE。
5. 断线或超时后停止显示当前位置，禁用播放。重新连接必须重新发送图形，不自动恢复输出。

BLE 不显示波特率；若模块通过 UART 接 FPGA，**模块与 FPGA 之间**的波特率仍需两端一致。BLE 模块不一定创建虚拟 COM 口。经典蓝牙 SPP 不在本适配范围；若系统已将某设备暴露为 COM 口，可按串口使用。[1]

界面示例：[连接界面](docs/ble-connection.png)，截图中的设备是自动化测试夹具。

## 3. 可替换的模块配置

默认采用 Nordic UART Service（NUS）的 UUID，仅作便于开发的起点，不代表硬件已选型。[2]

| 配置 | 默认值 | 方向 |
|---|---|---|
| 服务 | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` | NUS |
| 电脑发送通道 | `6e400002-b5a3-f393-e0a9-e50e24dcca9e` | 电脑写入 → 模块 RX |
| 电脑接收通道 | `6e400003-b5a3-f393-e0a9-e50e24dcca9e` | 模块 TX → 电脑通知 |

“连接设置”允许修改服务与收发 UUID（支持 16／32／128 位）、写入方式和分包字节上限。设置在本次程序运行内保留；连接期间不可修改。默认自动选择写入方式，优先有应答写入；仅支持无应答写入的模块使用其相应属性。接收通道必须支持 Notify 或 Indicate。

默认分包上限为 0，即按协商 MTU／特征写入上限自动取值，最多 512 字节；也可显式限制为 20 等较小值，最终不会超过系统报告的限值。[1] 不同模块即使 UUID 相同，也可能需要配对、专用启动命令或流控；当前没有这些专用适配。仅改 UUID 不能兼容任意厂家私有协议。

## 4. 字节流与反馈

- HAP3 原帧连同 CRC 和末尾 LF 一起拆包，不给每个 BLE 包额外加换行。对端按连续字节流重组，不能把一次 GATT 写入当作完整命令。
- 回传允许任意分包、半帧和多帧合并，沿用 `Decoder` 校验。通知先于 HELLO 订阅，以免漏掉快速应答。
- GATT 写入应答只说明传输层交付，不表示 FPGA 接受或执行。图形确认仍要求应用层 ACK 与匹配 STATE，真实设备须声明 `simulated=0`。
- 不自动重试控制命令。部分发送失败后中止连接，不把 STOP 拼接到尚未完成的帧后；设备需在失联后丢弃半帧，并执行自己的看门狗。
- 接收缓存限 64 KiB，溢出即断开并提示降低回传频率，不悄悄丢弃状态后继续控制。

## 5. 时间与容量边界

连接／服务发现／订阅总期限 15 秒；单个完整命令的 BLE 写入期限 1.5 秒。当前沿用 HAP3 草案的 ACK 2 秒、状态回传 2.5 秒、界面新鲜度 1.6 秒和控制完成 3.5 秒限制。这里是软件期限，不是已验证的无线性能。

完整 STATE 包含图形和全部相位，较复杂草图或大阵列会显著增加回传量。不能照搬 Demo 每 50 ms 一帧的运行回传频率。协议定稿时需共同确定实际最大帧、模块缓存、写入方式、回传周期和心跳期限，测量整条链路能否满足；不足时修改协议或缩小容量，不能仅延长电脑显示动画冒充反馈。模块桥接 UART 的缓存与速率也须纳入测试。

REMOTE 断开时尽力发送 STOP，失联后不能确认输出已停；LOCAL 允许 FPGA 独立运行。首版不支持多个电脑或手机同时控制。连接上电默认关闭输出的要求不变。

## 6. 模块选定后需确认

- 是否使用 NUS，实际 UUID 与读写属性，是否要求配对或专用初始化。
- 模块与 FPGA 的电气接口、UART 参数、缓冲容量和接收流控。
- 共同确认图形编码、命令与应答、完整状态回传、错误码、超时和断线行为；HAP3 可作为讨论起点。
- 用实体设备验证扫描、订阅、长帧双向传输、断线重连及看门狗，再判断是否需要调整草案。

## 7. 验证

```powershell
python -m unittest desktop_app.tests.test_ble -v
python -m desktop_app.tests.gui_ble_smoke
```

单元测试覆盖通道校验、MTU 分包、通知重组、缓存溢出、连接取消、发送超时、禁止半帧重试及 HAP3 双向会话。GUI 测试覆盖异步扫描、取消、配置、确认前禁止播放、反馈、掉线与重连。完整 `gui_smoke` 和 EXE `--self-test` 均包含 BLE 夹具场景，不打开真实蓝牙。
