# 阵列参数与接收反馈校准

更新日期：2026-09-30。已实现电脑 Demo、HAP3 扩展和 NUCLEO-F411RE 固件；尚无实板声学验证。参数化的是阵元几何与逐通道相位，不代表任意形状、距离、阵元数量都能产生足够触觉。

## 1. 现在可以做什么

- 用平面、球冠或显式三维坐标生成名义阵列文件，保存每个逻辑通道的位置、单位朝向与声速参数。
- 打印夹具生成器与坐标导出器共用 `geometry_from_parameters()`，避免两套间距公式不一致。现有 P1 平面 STL、原生零件和完全定义草图未改变。
- 固件根据坐标表在板内求相位。电脑连接三维固件时分块读取坐标，核对完整标识后才开放控制。
- 固定接收器，比较逐路和两路干涉的 40 kHz 电压幅值，求相对相位修正，复测通过后才应用。Demo 用已知合成误差演示同一流程。

## 2. 坐标与通道

P1 发声面中心为原点，正面看 XT30 在下方，x 向右、y 向上、z 朝手掌。其在腕托装配坐标中的名义平移是 `(0,0,53.2) mm`；控制算法使用局部原点，不能把 53.2 mm 再加到控制高度上。

`channel` 是逻辑输出编号，不是任意孔位编号。P1 的 0–15 从下到上、每行从左到右；必须按[固件说明第 4 节的接线表](../firmware/nucleo_f411re/README.md)连接，不能直接把逻辑编号当 R5 的 CH 编号。文件改变通道顺序会改变相位对应的换能器。

坐标单位为 mm；协议内部用整数 nm 和朝向 ppm，目的是稳定序列化，不表示纳米制造精度。表中位置是名义发声面中心，实际安装、器件差异和声学相位中心仍有误差。`geometry_id` 绑定坐标、通道顺序、朝向、行列信息、间距与声速。

## 3. 从机械参数生成固件

从仓库根目录执行：

```powershell
python hardware/mechanical/export_array.py
python firmware/nucleo_f411re/generate_geometry.py hardware/arrays/p1_flat_4x4.json
```

随后在 CubeIDE 正常 Build / Debug，仍使用板载 ST-LINK。也可运行 `python firmware/nucleo_f411re/build.py` 编译，脚本不会烧录。生成的 `include/array_geometry.h` 已提交，正常 IDE 构建不依赖 Python。

F411 输出引脚仍为 16 路；生成器拒绝 64/256 路文件。电脑模型支持最多 256 路，实际增路需要实现相应输出硬件，不是改一个数字就能完成。

## 4. 球冠与自定义阵列

```powershell
python -m desktop_app.array_geometry --rows 4 --cols 4 --pitch-mm 11 --radius-mm 80 --output hardware/arrays/example_sphere_4x4_R80.json
```

不传半径生成平面。球冠顶点为 z=0、球心为 `(0,0,R)`，阵元朝球心；间距表示 XY 投影间距。`--sound-speed-m-s` 可指定模型声速，默认 343。手工三维排列可编辑 JSON 的 `elements`，删除旧 `geometry_id` 后重新读取导出，由程序重算标识。

球冠文件仅为软件示例，**没有对应的可打印球冠夹具**；现有 P1 夹具只匹配 4×4、11 mm 平面 PCB。未来设计球冠时应让孔位、朝向和此文件共用参数，并另外验证器件碰撞、出线和装配。

调试模式 → 设备设置 → “导入阵列坐标”，可用于电脑预测和 Demo；连接真实设备后以固件回传为准。阵元图显示位置投影与朝向，声场仍采用理想点声源叠加，未加入器件指向性、反射或绝对声压标定。不能用归一化亮度证明球冠强度提升。

## 5. 接收板校准操作

1. 按既有接收板接线连接 PA0 与共地，确认接收前端没有削顶。保留原有分压，不改硬件。
2. 固定接收器并记录其相对阵列原点的位置，朝向阵列；保持接收增益不变。校准期间不移动接收器，也不放手干扰声场。
3. 连接新版固件，停止输出并选择电脑控制。进入“调试模式 → 实测数据 → 相位校准”，填写位置与参考通道。
4. 点击“开始校准”。程序暂时使用固定点、40 kHz、64 级相位、无调制、连续测试载波。停止时测噪声；逐路测幅值；与参考通道配对测四个相位，再复测修正结果。
5. 全部通过后，修正值保存至板端 RAM，原图形恢复且保持停止。重新发送图形后可播放；“保存校准文件”可供断电后重新导入。

可以随时取消。停止、远程失联或新握手会撤销临时测试修正；测量失败不发送保存命令。应用阶段发生异常时，程序尝试恢复旧修正；若失联导致恢复无法确认，会明确报告未知状态，须重连核实。固件复位清除 RAM 修正，校准文件需主动导入；模拟文件不能导入真实设备。换接线、更换器件、调整装配或改变声速参数后应重新校准。

## 6. 求解方法与质量检查

接收器固定时，两路复声压的相位差随目标通道的命令相位 θ 改变。在线性稳定链路中，40 kHz 幅值平方满足 `P(θ)=A²+B²+2AB cos(δ+θ)`。测量 θ=0°、90°、180°、270°，由 `(P0-P180)/2` 与 `(P270-P90)/2` 求 δ，再施加 −δ 的量化修正。这里不读取 ADC 的绝对相位，因此不要求 ADC 窗口与发射时钟同相启动。

每个条件默认重复三次。程序核对启动标识、配置版本、运行标志和采样时间，拒绝过期窗口；检查噪声、重复稳定性、ADC 边界、四步拟合及修正后的实际幅值。检查阈值是初始工程选取，须实测调整。ADC 未触轨不代表模拟前端没削顶，拟合检查也不能证明不存在所有失真。

## 7. 能修正与不能推断的内容

这得到的是**固定测点、固定频率下的相对通道相位修正**。它会混合器件、驱动、局部传播和反射的影响；位置误差引起的修正在另一个目标位置不一定同样有效。单点反馈不能唯一确定所有阵元的实际三维坐标、朝向或全空间声场，也没有自动幅度均衡和手掌跟踪。

扩大工作区域前，应固定多个已知接收位置复测，再决定是否建立分区校准表。球冠的名义几何已可用于求相位，但机械装配与有效扫描区域尚待验证。

## 8. 验证与兼容

自动检查包括平面夹具坐标一致性、球冠等距相位、三维 C/Python 相位一致性、256 路分块回读、标识损坏、通道屏蔽、修正原子性、取消恢复及合成反馈求解。还通过实际 C 协议内核与合成 ADC 回调完成 16 路校准，这是宿主机软件测试，不是实板测量。电脑新增界面可在 Demo 查看。

旧平面协议继续可用；手机端保留平面控制，遇到 `EXPLICIT_XYZ` 明确提示使用新版电脑端，不把三维阵列误解为平面。手机尚无三维坐标页和校准页。真实 FPGA RTL 仍待实现。
