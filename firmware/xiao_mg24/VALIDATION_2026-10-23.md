# MG24 连续采样溢出修复与实板验证

日期：2026-10-23。用户要求修复自动校准中的 `ADC_OVERFLOW`。本次更新 MG24 USB 应用，保留引导程序、采样率、200 点窗口、模拟量程和校准判据；没有修改 FPGA 输出逻辑。

## 问题与依据

此前三次采样通过，不能证明连续采样可靠。发射关闭的相同条件下，40 次短测通过；随后 200 次出现 4 次 `ADC_OVERFLOW`，196 次成功。另一次在第 52 次请求复现。故该报错无需通道 3 发射就能出现，不能归因于 U102 焊点或模拟输入触轨。

`sampler.h` 原来只用有限 DMA 描述符保存 200 点，然后由 DMA 完成中断关闭 IADC 定时器。DMA 停止搬运到 CPU 执行回调之间，IADC 仍可持续往 FIFO 写数据。板载 DMA IRQ 优先级为 8，RTOS/其他中断可以延迟回调；旧固件成功窗口软件时间戳差出现 518、519、549、550、580 微秒。失败后读出 `sampler.done_ = true`，DMA 窗口已完成；对应软件时间戳差为 549 微秒。该状态和复测对比支持“窗口结束后的停止竞态”，不是已经测量出逐个样本的真实间隔。

证据：`before-fix.jsonl`、`before-fix-long.jsonl`、`overflow-state3.log`，均在 `.runtime/mg24/hardware/2026-10-23/`。板内状态读取发生在失败后，不在采样中暂停 CPU。

## 修复

`firmware/xiao_mg24/receiver/sampler.h` 改为两个相连的 DMA 描述符：

1. 第一个只搬运 200 个数据，关闭自身完成中断并链接下一个描述符。
2. 第二个执行硬件立即写，将 `TIMERDIS | SINGLESTOP` 写入 IADC CMD，随后才触发完成中断。它无需额外采样请求，不循环回写样本。

CPU 回调仅记录完成时间和标志。`poll()` 仍先检查硬件 FIFO 溢出及其他错误，未忽略错误、自动重采或把失败数据伪装成成功。停止、取消及下次采样前清理保持原逻辑。结束时间戳仍是 CPU 回调时间，不是硬件停止的精确时刻。

依据为锁定 Silicon Labs Arduino Core 5.0.0 的 `em_ldma.h` 中 LINKREL_P2M_WORD 与 SINGLE_WRITE 定义，以及 [Silicon Labs LDMA 立即写描述符说明](https://docs.silabs.com/gecko-platform/4.1/emlib/api/efr32xg12/group-ldma)。

## 校准剩余问题

真实复测记录：`.runtime/calibration/calibration_20261023_200434_783101.jsonl`。

- 参考通道 0 的 40 kHz 峰值约 57–58 mV。
- 通道 1 单路约 114 mV，通道 2 单路约 131–133 mV。
- 通道 3（U102）单路仅 0.210、0.215、0.272 mV，仍接近背景。
- 57 次后状态 state=5/error=4/channel=3，输出关闭，没有提交修正表或生成成功校准文件。

采样溢出问题已在本次有限实板复测中消除；U102 对应输出链路的弱信号是独立未解决问题。焊点检查正常不能排除移位寄存器输出、驱动、换能器或实际通道对应的问题，下一步需要有针对性观察该路电信号，不应直接断言换能器损坏或绕过失败判据。
