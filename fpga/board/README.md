# 上板工程：怎么建、怎么烧、上电先看什么

更新日期：2026-10-06。

2026-10-12 审查补充：串口和按键已加入两级输入同步；上电复位与启动标识有明确初值。
第一次综合仍须核查初始化设置和同步器路径。当前 `boot` 仅用于同次上电期间区分复位，
断电重启可能重复，跨断电唯一标识仍待设计。数字仿真通过不代表已经完成上板验证。

这一份是**板子到手之后照着做**的清单。逻辑本身在 `fpga/rtl/` 里，这里只讲工具那边
怎么把这些文件变成一个能烧进板子的工程。

## 0. 板卡与工具

| 项目 | 值 | 来源 |
|---|---|---|
| 开发板 | Sipeed Tang Mega 60K（NEO DOCK 底板） | 项目选定 |
| FPGA 型号 | **GW5AT-LV60PG484A**（封装 PBG484A，Device Version **B**） | Sipeed 官方 wiki |
| 板上时钟 | **50 MHz**，引脚 **V22** | 官方例程的 sdc：`create_clock ... -period 20` |
| 用户按键 | Y12、AA13、AB13（低有效，**必须开内部上拉**） | 官方例程的 cst |
| 软件 | 高云云源软件（Gowin EDA），选型号时三个参数都要对上 | 

因为板上就是 50 MHz，和固件默认的 `CLK_HZ = 50_000_000` 一致，**不需要锁相环（PLL）**：
串口分频 434、每 10 µs 一拍（500 个时钟）都是按 50 MHz 算好的。将来要跑更快的时钟
再例化 Gowin 的 PLL IP，同时把 `CLK_HZ` 和 `.sdc` 一起改。

1. Gowin EDA → New Project → 器件选 **GW5AT-LV60PG484A / PBG484A / B**。

## 2. 上板前必须自己核实的四件事

这四件事在电脑上没有答案，只能在板子/原理图上确认：

1. **串口引脚**。板载 FT2232 的 UART 接哪两个 FPGA 引脚，只有官方的「全引脚约束」表里有
   （网上没有公开文本）。`.cst` 现在先把串口临时放在相机口的两个空闲脚（Y13/AA14）上，
   你拿一根 USB-TTL 接上去就能调通；核实到板载串口引脚后改这两行即可。**注意别把 TX/RX 接反。**
2. **通道引脚**。这一版是 **8 路**（对应计划里"先验证少量驱动通道"这一步）：左边 PMOD 的
   T18/R18/R17/P16 + 相机口的 P14/P15/R16/R14，全部在 Bank 6（3.3 V）。

   ⚠️ **为什么不是 16 路**：板子两个 PMOD 里的 P19/R19/T21/U21 是芯片的**配置复用脚**
   （D06/D07/D04/D05），命令行工程里布局阶段会直接报
   `PR2017 ... dedicated pin (CPU)`，跑不通。想把这 4 个脚拿回来（恢复 4×4 的 16 路）：
   在 Gowin IDE 里打开工程 → `Project → Configuration → Multipurpose Pin`，
   把 Download Mode 选成 `JTAG` 后重新布局；能过就把 `.cst` 里那 8 路扩成 16 路，
   同时把 `board_top` 的 `HW_ROWS` 改回 4。

   各 bank 的电压（查器件数据文件 `IDE\data\device\GW5AT-60B\PBGA484A.json` 得到）：

   | Bank | 电压 | 我们用的脚 |
   |---|---|---|
   | 5 | 3.3 V | J16、J20 |
   | 6 | 3.3 V | T18 R18 R17 P16 P14 P15 R16 R14 N15 |
   | 7 | 3.3 V | V22（时钟，50 MHz） |
   | 8 | 3.3 V | Y21、AA14 |
   | 9 | **1.5 V** | Y12、AA13、AB13（三个用户按键） |

   只有 Bank 9 是 1.5 V，所以那三个脚只能给按键；把 3.3 V 信号放到 Bank 9 上会报
   `CT1136 Bank 9 vccio(1.5) is locked ... conflicting BANK_VCCIO`（我们踩过）。
3. **驱动拓扑**。单端驱动 → 用 `array_pos`、`OUT_DEAD_CYC` 填 0（**当前工程就是这样**）；
   半桥要互补输入 → 先把 `board_top` 那行端口改成同时引出 `array_neg`，在 `.cst` 里给
   `array_neg[0..15]` 分配一组自己的引脚（不能和通道重脚），再把 `OUT_DEAD_CYC` 填成
   死区拍数（4 拍 @50 MHz = 80 ns，够不够要看驱动芯片手册的上升/下降时间）。
   `array_neg` 现在故意没引出：顶层端口没有约束时工具会自动乱摆引脚，可能撞到 DDR/HDMI。
4. **相位符号**。参考实现的约定是「相位码越大越提前」，固件按这个实现；但真实声场取决于
   换能器和驱动级的极性，**必须用麦克风在一个已知位置上量一次**。量反了焦点会跑到镜像点。

## 3. 上电第一件事：先不接阵列，只接串口

顺序很重要，一次只加一样东西，出了问题才知道是谁的问题：

1. 只接串口和下载线，阵列先不接。烧进去之后用上位机「连接」。
2. 应当收到 HELLO 应答：`device=FPGA`、`simulated=0`、`hw_rows=4`、`boot=` 是一个非 0 的数。
3. 板上 5 颗状态灯的含义（从左到右）：输出正在驱动 / 正在扫描 / 走步器在跑 /
   本地模式 / 串口在发。
4. 按下面板上的「播放」键：灯亮、状态帧变成 `state=RUNNING`（注意上位机默认是远程模式，
   要用按键得先 `MODE value=LOCAL`，或者干脆不接电脑、板子自己跑）。
5. 示波器/逻辑分析仪先量空载波形：频率 40 kHz、16 路之间有相位差、暂停时全部拉低。
6. 再接驱动板 + 一个换能器，量电压、电流、温升；最后才接整个 4×4 阵列。

## 4. 综合时看什么

### 4.1 第一次跑的结果（2026-10-12 实测，命令行 build.tcl）

| 项目 | 实测 | 说明 |
|---|---|---|
| 比特流 | 生成成功（`board_top.fs`，18.8 MB） | 可以直接烧板子 |
| LUT | **8590 / 59904（14%）** | 余量很大，加 8×8 也够 |
| 寄存器 | 5886 | — |
| ALU | 2651 | GW5A 的算术单元 |
| BSRAM / 分布式 RAM | 24 块 / 37 块 | 大表（行缓冲、节拍表、相位表）都进了块存储 ✓ |
| DSP（MULT27X36） | 24 / 118（20%） | 除法/开方/乘法用掉的多 |
| 时序（第一次） | 25 条 setup 违例，最差 **−13.5 ns**，全部集中在轨迹编译模块 | 见下 |
| 时序（把编译模块流水化之后） | 最差 **−1.19 ns**，25 条，但**散在输出级/编译/发送等各模块** | 见下：这是**时钟走线**的锅，不是某个模块的锅 |

⚠️ **结论**：现在可以烧板子验证"串口握手 / 状态帧 / 按键 / 状态灯 / 上电复位"这些路径，
但**轨迹输出先别信**——时序还没达标，编译出来的节拍表可能是错的。修完再用 START。

**第一处（已修）**：配置阶段的关键路径原来是「`blank_us` → 除以 10 → 乘笔数 → 再乘 `repeat` → 比较」，
全挤在一个时钟周期里，36.9 ns，slack −13.5 ns。`hap2_traj_plan` 里把它拆成三级寄存器
（`budget_q`/`blank_beats_q` → `budget_full`/`blank_total_q` → 判定），多花两拍，
最差 slack 从 −13.5 ns 变成 −1.19 ns。语义一字未改（同一个乘积、同一个比较）。

**第二处（待修）**：剩下的 25 条违例只有 −1.0～−1.2 ns，而且**散落在输出级、轨迹编译、串口发送
等互不相关的模块上**——这种"到处都差一点点"的形态，配合布局布线时的告警
`PR1014: Generic routing resource will be used to clock signal 'clk_d' ... may lead to
excessive delay or skew`，说明瓶颈是**时钟没有走全局时钟资源**（走了普通布线，
引入了额外偏斜），而不是某个模块逻辑太长。

为什么会这样：板上的 50 MHz 在 V22，而这个球在器件里叫 EMCCLK——**它也是一个配置复用脚**
（和前面那 4 个通道脚同一类问题）。下一步要么在 IDE 里把这颗芯片的复用脚配置改对
（`Multipurpose Pin`，能同时把 16 路通道的 4 个脚拿回来），要么在板级顶层里例化一个
Gowin 的 PLL/时钟缓冲原语，让时钟输出自动走全局网络。

**存储**（按代码里的表算出来的，是估算不是综合报告）：

| 表 | 大小 |
|---|---|
| 串口行缓冲 | 4096 B = 32 Kbit |
| 草图原文缓冲（上下两半） | 8192 B = 64 Kbit |
| 点表 × 2（草图 + 预设图形） | 各约 11 Kbit |
| 节拍表（双缓冲，每半 512 行 × 95 位） | 约 97 Kbit |
| 第一趟的中间表（长度、dx、dy） | 约 25 Kbit |
| 相位表 + 状态快照 | 约 6 Kbit |
| 应答模板（常量 ROM） | 约 7 Kbit |
| **合计** | **约 250 Kbit ≈ 32 KB** |

按 36 Kbit 一块的 BSRAM 算大约 8～10 块，对 60K 级别的器件很宽松。

**算术单元**（这些是占 LUT/DSP 的大头，具体数字以综合报告为准）：

- 相位计算里有 `PH_PIPE` 条 42 位开方流水线（默认 4 条），每条是一个逐位逼近的移位减法器；
- 56 位除法器 3 个（轨迹编译、输出级算载波增量、相位计算算常数）；
- 21 位开方 1 个（轨迹编译算段长）；
- 节拍表、相位表都是「同步读」的寄存器堆，综合成 BSRAM 还是分布式 RAM 由工具决定。

想省资源就把 `PH_PIPE` 调小（4→2），代价是相位表扫一遍的时间变长——4×4 时
PIPE=4 大约 100 个时钟扫完，离一个节拍的 500 个时钟（10 µs @50 MHz）还有很大余量。

## 5. 换 8×8（64 路）时要动什么

1. `board_top` 的参数：`HW_ROWS = 8`、`HW_COLS = 8`，`PH_PIPE` 建议 8。
2. `.cst` 里补 `array_pos[16..63]` 的引脚（需要 64 个通道，两个 PMOD 已经不够，
   那时候驱动板应该有自己的接口定义了）。
3. 复位重启一次（`boot` 会变），上位机会重新握手，握手应答里的 `hw_rows/hw_cols` 会变成 8。
4. 仿真里已经先跑过一遍 8×8（`tb_phase.v` 的 8×8 用例 + `tb_top8.v` 的端到端），
   上板前可以先看那两条有没有过。
