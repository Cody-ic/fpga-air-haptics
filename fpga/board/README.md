## 当前构建入口：选择阵列、接线与芯片版本

当前支持两种独立板级配置，共用控制内核，不能把旧 4×4 比特流直接接到 8×8 R2。

| 阵列 | 顶层 | 引脚约束 | 构建产物 |
|---|---|---|---|
| 4×4 R5，11 mm | `board_top` | 默认 `tang_mega_138k_pro.cst`；旧接线用 `_pmod.cst` | `haptics138kpro_j23/impl/pnr/board_top.fs`；旧接线目录为 `haptics138kpro/` |
| 8×8 R2，10.3 mm | `board_shift_top` | [tang_mega_138k_pro_8x8.cst](tang_mega_138k_pro_8x8.cst) | `haptics138kpro_8x8/impl/pnr/board_shift_top.fs` |

在本目录运行商业版 Gowin 的 `gw_sh.exe build.tcl`。环境变量 `HAPTICS_ARRAY=4x4/8x8`
选择阵列，`HAPTICS_PINOUT=j23/pmod` 选择接线（8×8 只支持 J23），
`HAPTICS_DEVICE_VERSION=B/C` 选择实际芯片版本；默认值依次为 `4x4`、`j23`、`B`。
JTAG（Joint Test Action Group，联合测试工作组）识别码不能单独证明 B/C 版本。
切换配置时核对构建日志中的阵列、顶层、约束和输出目录；编译不会自动烧录。

### XIAO MG24 接收/无线版本（2026-10-19）

设置 `HAPTICS_RECEIVER=mg24`；默认 `adcs7476` 保留原有接收方案。
4×4 新顶层为 `board_mg24_top`，产物在 `haptics138kpro_j23_mg24/impl/pnr/board_mg24_top.fs`；
8×8 为 `board_shift_mg24_top`，产物在 `haptics138kpro_8x8_mg24/impl/pnr/board_shift_mg24_top.fs`。
对应使用 `_mg24.cst` 约束，要求 `HAPTICS_PINOUT=j23`。

此版本的收发分别通过 J22-8/L24 与 J22-6/T24，J22-5/R17 输出采样触发，
电脑连接 MG24 自身串口或蓝牙。板载调试串口 N16/P15 不充当第二控制入口。
完整方向、共地、D0 模拟输入和两种宏模式见 [MG24 使用说明](../../firmware/xiao_mg24/README.md)。
四配置的引脚、资源、时序及未验证项目见[本轮核验](RELEASE_2026-10-19_MG24.md)。

**8×8 使用 12 条移位控制信号及共地，不再增加 64 个直接输出引脚。**
完整 J23→H1 接线、25 MHz 时钟、64 档上限、零帧初始化和停止行为，
见 [FPGA 工程说明](../README.md#4×4-与-8×8-板级配置2026-10-18)。
J23-11 的 5 V 留空，J23-12 接 H1-1/2 共地，12 V 从发射板 XT30 独立输入。
8×8 的四颗用户灯低电平点亮：输出请求、扫描、走步器运行、移位故障。
第 0 灯表示逻辑请求，并非实际 OE（Output Enable，输出使能）引脚回读。

逐通道校准现已覆盖 4×4 R5 / 11 mm 和 8×8 R2 / 10.3 mm，包含完整 64 位掩码与 64 路补偿。

需要重新发送图形配置后才能播放，避免重连时恢复通道掩码造成意外输出。

## 2026-10-15：默认输出改接 J23，保留旧接线回退入口

J23 是底板原理图第 16 页的 SDRAM CONN.（同步动态随机存储器连接器）。

信号采用 3.3 V 电平，驱动板与 12 针共地。不要同时插存储器扩展模块。
表内针号按原理图与实物 1 针标记核对，不要根据原理图左右位置猜实物朝向。

默认构建选 `tang_mega_138k_pro.cst`，输出在
`haptics138kpro_j23/impl/pnr/board_top.fs`，不会覆盖已有的旧版烧录文件。
若当前终端曾设置过旧版选择，可先执行 `$env:HAPTICS_PINOUT = 'j23'` 再运行 `build.tcl`。

回退有两种方式：直接重新烧录已经保存的
`haptics138kpro/impl/pnr/board_top.fs`；或者在 PowerShell 中执行下面的命令，

### 接收采样的硬件边界

Tang MEGA 138K Pro 的普通 FPGA 引脚只能判断数字高低，不能直接量接收板输出的连续模拟电压。当前代码通过外接 ADCS7476 转换：400 kS/s、12 位、每次 200 点，采样结束后用串口回传。PMOD0 预留三根数字线：SCLK=`T24`、CS_N=`R17`、SDATA=`L24`；4×4 与 8×8 两套约束一致，不占用 J23 发射接口。

这只表示数字接口已经实现。ADCS7476 小板、3.3 V 供电与去耦、模拟输入建立、抗混叠和真实接收波形均未实测；接收板模拟输出不能直接接普通 FPGA 引脚。上板前按 [接收采样方案](../接收采样方案.md) 核对接线与电气范围，现阶段 STM32F411 验证平台仍可作为实测对照。

## 下载卡在 0%：检查下载器的 USB 位置

2026-10-14 实测（商业版 IDE V1.9.12.04）。症状：板子开着机、流水灯在跑、两个电源灯都亮、
USB 插的是 `USB JTAG&UART` 口，电脑也认得下载器（设备管理器里两个 USB Serial Converter
＋两个 COM 口），但 Programmer 一烧就**卡在 0%**，命令行 `--scan` 也**永远等不到应答**；
换个电脑（队友的）用同一根线同一块板子却能烧。

这次排查记录中，选中下载器的 **location 561** 后可以扫描和下载，**562** 无应答。
这是该电脑、该次连接的记录，不是所有电脑通用的编号；更换 USB 口后编号也可能改变。
设备管理器识别到设备，并不等于 Gowin 已打开正确的调试接口。

**图形界面**：`Edit → Setting → Cable Setting` → **Query** → 选择能正确扫描器件的
USB location → **Save**。不要照抄其他电脑的编号。

**命令行**：先列出下载器，再用当前编号只读扫描。以下 561 是上述记录中的示例：

```powershell
$programmer = 'D:\tools\Gowin-1.9.12.04\Programmer\bin\programmer_cli.exe'
& $programmer --scan-cables
& $programmer --scan --cable-index 4 --location 561

# 确认扫描成功后，填写本机生成的比特流路径；此命令会下载程序。
& $programmer `
  --device GW5AST-138B --run 2 `
  --fsFile 'D:\FPGADev\haptics138kpro-focus11mm\board_top_4x4_11mm.fs' `
  --cable-index 4 --location 561 --frequency 2.5MHz
```

`--run 2` 是 SRAM 编程（断电即失）；要固化到 flash 再另说。
`--location` 与 `--channel` 的优先级见安装目录中的 Programmer 命令行手册第 4.4 节。
扫描返回 `0x0001081B` 说明能读到对应器件，但 **B/C 共用这个识别码**，不能据此确认版本。
当前 B 版配置已通过临时下载和串口回读；最终版本仍按第 0 节核对芯片标记。

是 C 就是 C）。扫描读到的 `0x0001081B` 同时对应 B/C，不能凭这个识别码确认版本。
当前脚本与首轮临时下载使用 B 版；制作最终配置前仍须核对芯片标记，C 版应修改
`build.tcl` 的 `-device_version` 后重新生成。

板子上有两个 USB 口：**`USB JTAG&UART`**（板载下载器 + 一路串口，烧录和联调都用这个；
串口对应 FPGA 的 N16/P15，不需要外接 USB-TTL）和「自定义 USB/软接」（我们不用）。

因为板上就是 50 MHz，和固件默认的 `CLK_HZ = 50_000_000` 一致，**不需要锁相环（PLL）**：
串口分频 434、每 10 µs 一拍（500 个时钟）都是按 50 MHz 算好的。将来要跑更快的时钟
再例化 Gowin 的 PLL IP，同时把 `CLK_HZ` 和 `.sdc` 一起改。

## 2. 上板前必须自己核实的四件事

这四件事在电脑上没有答案，只能在板子/原理图上确认：

1. **串口引脚**。当前约束为接收 `N16`、发送 `P15`，使用板载调试串口，115200、8N1。
   `P16` 是 50 MHz 时钟输入，不能按旧说明接作串口。若外接 3.3 V 串口模块，
   模块 TX → N16、模块 RX ← P15，并共地；需先确认与板载调试器的连接不冲突。
2. **通道引脚**。**16 路（4×4）已经能布局布线并生成比特流** ✓

   关键是 `build.tcl` 里这两条（不是可选项）：

   ```tcl
   set_option -use_cpu_as_gpio   1
   set_option -use_sspi_as_gpio  1
   ```

   138K 上有一半引脚是**配置复用脚**，不放开会在布局阶段直接报
   `PR2017 ... dedicated pin (CPU/SSPI)`：

   | 引脚 | 器件文件里的 CFG 字段 | 要哪个开关 |
   |---|---|---|
   | P19 | D06/SSPI_CLK | CPU + SSPI |
   | R19 | D07/SSPI_WPN | CPU + SSPI |
   | U21 | D05/SI | CPU + SSPI |
   | T20 | D08/SO | CPU + SSPI |
   | Y21 | SSPI_CS_N（**只属于 SSPI**） | 只要 SSPI |
   | T21 | D04（纯 CPU） | 只要 CPU |

   ⚠️ 60K 上这几个脚**没有** SSPI 这层别名，所以以前只开 CPU 就够了；换板子之后
   必须**两条都开**才能布局。官方 138K 例程（pmod_led）的工程配置里 CPU 和 SSPI
   两项也都是 true，两边一致。换成 138K Pro（676 球）之后这两条先原样留着——
   在 676 球的新器件文件里到底哪几个脚是复用脚，要等商业版 IDE 装好、能建工程之后再核。

   ⚠️ 走过弯路，记一下：**改文件没用**。`IDE\share\config\device.cfg`（工具模板）改了
   不生效；工程里的 `impl\pnr\device.cfg` 每次跑都会被重新生成，改了会被覆盖回去。
   IDE 里那个 Multipurpose/复用引脚的对话框我们也一直没找到，
   最后是**命令行开关**解决的。

   切换 8 路/16 路：`board_top` 的 `HW_ROWS`（4 = 16 路，2 = 8 路），
   同时 `.cst` 里把 `array_pos[8..15]` 那几行注释/取消注释。

  我们用的脚现在全部来自官方 Pro 资料，电平统一写 `IO_TYPE=LVCMOS33 / BANK_VCCIO=3.3`：

  | 用途 | 引脚 | 来源 |
  |---|---|---|
  | 时钟 50 MHz | P16 | 官方 Pro 例程的 sdc |
  | 按键 ×3 | K16（复位）、F15、G15 | 官方全引脚约束 |
  | 串口 | N16（收）、P15（发） | 底板原理图（BL616 的 UART 经 0 Ω 电阻接这两脚） |
  | 16 路输出 | 默认 J23 的 1～10、13～18 针；旧版为 PMOD1 八个 + PMOD2 八个 | 见文首接线表与两份引脚约束 |
  | 状态灯 ×3 | R26、J14、L20（**低电平点亮**） | 官方 LED 例程（`assign led = ~led_reg`） |

  一个坑记一下：**不同板子的 bank 编号和电压完全不是一套**，照抄会翻车。60K 上那三个
  按键在 1.5 V 的 bank 9 里（只能写 LVCMOS15），而 138K（非 Pro）上它们在 3.3 V 的
  Bank 5 里；当时照抄了 60K 的 LVCMOS15，那一行就把整个 bank 锁成 1.5 V，同 bank 的
  另一个脚再写 LVCMOS33 就报 `CT1136 ... vccio(1.5) is locked` ✗。现在所有脚的电平
  都按对应板子的官方资料写。
3. **驱动拓扑**。单端驱动 → 用 `array_pos`、`OUT_DEAD_CYC` 填 0（**当前工程就是这样**）；
   半桥要互补输入 → 先把 `board_top` 那行端口改成同时引出 `array_neg`，在 `.cst` 里给
   `array_neg[0..15]` 分配一组自己的引脚（不能和通道重脚），再把 `OUT_DEAD_CYC` 填成
   死区拍数（4 拍 @50 MHz = 80 ns，够不够要看驱动芯片手册的上升/下降时间）。
   `array_neg` 现在故意没引出：顶层端口没有约束时工具会自动乱摆引脚，可能撞到 DDR/HDMI。
4. **阵列几何与相位**。R5 板间距为 11 mm，通道应按实际换能器位置连接。
   求解码 `-r*f/c` 配合输出级 `acc - offset`；同时检查逐路极性、驱动幅度及接收信号。
   数字仿真与串口回读不能代替声场测量。

## 3. 上电第一件事：先不接阵列，只接串口

顺序很重要，一次只加一样东西，出了问题才知道是谁的问题：

1. 只接串口和下载线，阵列先不接。烧进去之后用上位机「连接」。
2. 应当收到 HELLO 应答：`device=FPGA`、`simulated=0`、`hw_rows=4`、`boot=` 是一个非 0 的数。
3. 当前使用 3 颗状态灯：`led[0]` 输出使能、`led[1]` 正在扫描、`led[2]` 走步器在跑，
   都是低电平点亮。本地模式和串口状态通过回传信息查看。
4. 按下面板上的「播放」键：灯亮、状态帧变成 `state=RUNNING`（注意上位机默认是远程模式，
   要用按键得先 `MODE value=LOCAL`，或者干脆不接电脑、板子自己跑）。
5. 示波器/逻辑分析仪先量空载波形：频率 40 kHz、16 路之间有相位差、暂停时全部拉低。
6. 再接驱动板 + 一个换能器，量电压、电流、温升；最后才接整个 4×4 阵列。

历史记录（60K 时期的两处时序问题，都已修完，留档）：

**第一处（已修）**：配置阶段的关键路径原来是「`blank_us` → 除以 10 → 乘笔数 → 再乘 `repeat` → 比较」，
全挤在一个时钟周期里，36.9 ns，slack −13.5 ns。`hap2_traj_plan` 里把它拆成三级寄存器
（`budget_q`/`blank_beats_q` → `budget_full`/`blank_total_q` → 判定），多花两拍，
最差 slack 从 −13.5 ns 变成 −1.19 ns。语义一字未改（同一个乘积、同一个比较）。

**第二处（已修）**：剩下的 −1.0～−1.2 ns 违例散落在输出级、轨迹编译、串口发送等模块。
同期存在 `PR1014` 告警，但单凭这个告警不能判断时钟资源或认定偏斜是唯一瓶颈。
后来通过**分四处把长路径拆短**解决：
`fix_div` 的倒计数器缩到 6 位、`hap2_out` 的占空比门限改成寄存器、
`hap2_traj_plan` 的拍数计算拆成三拍并改走共享除法器、`hap2_field_parse` 的键名比较打一拍。

⚠️ 那个 `PR1014` 告警在 484 球那一轮出现过 1 次。它是告警不是错误，时序分析显示所有
路径都过；含义是「时钟走了普通布线，可能带来额外偏斜」。上板后用示波器量 40 kHz 波形时
留意有没有明显抖动；真有问题再回头处理（加 PLL / 时钟缓冲原语）。

**存储**（按代码里的表算出来的，是估算不是综合报告）：

| 表 | 大小 |
|---|---|
| 串口行缓冲 | 8192 B = 64 Kbit |
| 草图原文缓冲（上下两半） | 8192 B = 64 Kbit |
| 点表 × 2（草图 + 预设图形） | 各约 11 Kbit |
| 节拍表（双缓冲，每半 512 行 × 95 位） | 约 97 Kbit |
| 第一趟的中间表（长度、dx、dy） | 约 25 Kbit |
| 相位表 + 状态快照 | 约 6 Kbit |
| 应答模板（常量 ROM） | 约 7 Kbit |
| **合计** | **约 282 Kbit ≈ 35 KB** |

按 36 Kbit 一块的 BSRAM 算大约 8～10 块；实际综合出来用了 **32 块 BSRAM（10%）**，
对 138K 级别的器件很宽松。

**算术单元**（这些是占 LUT/DSP 的大头，具体数字以综合报告为准）：

- 相位计算里有 `PH_PIPE` 条 42 位开方流水线（默认 4 条），每条是一个逐位逼近的移位减法器；
- 56 位除法器 3 个（轨迹编译、输出级算载波增量、相位计算算常数）；
- 21 位开方 1 个（轨迹编译算段长）；
- 节拍表、相位表都是「同步读」的寄存器堆，综合成 BSRAM 还是分布式 RAM 由工具决定。

想省资源就把 `PH_PIPE` 调小（4→2），代价是相位表扫一遍的时间变长——4×4 时
PIPE=4 大约 100 个时钟扫完，离一个节拍的 500 个时钟（10 µs @50 MHz）还有很大余量。

## 5. 切换到 8×8 R2

1. 设 `HAPTICS_ARRAY=8x8`、`HAPTICS_PINOUT=j23`，确认器件 B/C 版本后执行同一个 `build.tcl`。
   脚本选择 `board_shift_top`、8×8 / 10300 µm / 并行 8 和独立约束，保留 4×4 构建入口。
2. 按文首链接接 J23→H1 的移位时钟、锁存、使能、清零、8 路 DATA 和共地。
   不把 `array_pos[0..63]` 直接接进 H1，也不沿用 4×4 线序。
3. 加载正确产物后重新握手，应声明 `hw_rows=8 hw_cols=8 hw_pitch_um=10300`。
   8×8 物理接口限制最多 64 相位档，50 MHz 下载波最高约 41118 Hz；40 kHz 为首轮工作值。
4. 先跑 `tb_shift595.v`、`tb_shift_wave.v`、`tb_board_shift.v` 与两种规模的 `tb_state_snapshot.v`，
   再核对商业版布局布线结果，最后实测 H1 时序、输出关闭和驱动波形。
   历史 `tb_top8.v` 的 10 mm 并行内核测试不能代替这些 R2 适配检查。
