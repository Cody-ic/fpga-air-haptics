# 4×4 / 8×8 数字实现核验：2026-10-18

## 范围

代码修复与电脑端验证，未进行本轮实物下载、驱动板测量或触觉实验。
源码基于 `codex/fpga-firmware` 的 `631a564`，并纳入当前主线文档；
生产逻辑修复提交为 `06ffe93`。商业版 Gowin V1.9.12.04，
GW5AST-LV138FPG676AC1/I0、器件版本 **B**、50 MHz、J23 接线。
B 只是本次构建选择，实际芯片 B/C 须看器件标记，不能由共用识别码推定。

## 修复内容

- STATE 的配置、图形原文、长度与相位一同冻结，正在发送的文本不会被后续两次 CONFIG 覆写。
- 样本序号扩为 32 位，十进制发送保留负坐标并正确处理完整无符号 32 位数值。
- 每段结束回到精确终点，消除重复播放时的跨段、跨圈位置漂移。
- 新增 8×8 R2 / 10.3 mm 的八路并行移位适配、独立顶层及引脚约束；保留 4×4 R5 / 11 mm 直接输出。
- 移位接口限制为最多 64 档、载波不超过 `CLK_HZ/(64*19)`；不支持的配置原子拒绝。
  拒绝的影子配置不得污染本地 NEXT 或首次 PLAY，提交前再次核对输出预算。
- 上电、STOP、复位和移位故障关闭 OE，初始化／停止锁存零帧，重新启动等待完整新帧。
  移位故障快照返回 `output=0 reason=OUTPUT_FAULT`。

## 数字回归

在 Ubuntu-24.04 / Verilator 5.020 运行：

```bash
python fpga/tb/gen_vectors.py
BUILD_DIR=/tmp/haptics-rtl-fix-full bash fpga/tb/run_verilator.sh
```

**19 组全部通过，脚本退出码 0。** 原 13 组回归之外，新增：

| 测试 | 本次结果 |
|---|---|
| 精确终点与跨圈轨迹 | 1,023,718 项，含最大点数、暂停恢复、拒绝后保留旧图形 |
| 595 引脚行为模型 | 26,276 项，含 19 个 STOP 时机和快速重启 |
| 实际输出级 → 595 模型 | 126,045 项；64 路周期均 1250 拍，高电平均 625 拍；40 kHz / 50% |
| 64 档物理相位 | 逐路相位差误差不超过 1 个系统时钟；采样间隔为 19/20 拍 |
| 两种板级顶层真实串口线 | 3,312,872 项；8×8 收发 36 帧、4×4 收发 6 帧 |
| 4×4 长状态快照 | 131 项 / 19 帧，含 4095 字节、连续两次改图及计数边界 |

另用真实上位机 `decode` / `Snapshot.parse` 检查两套串口日志，
每套 19 帧、9 份状态均能解析；包含 65536、2147483648、4294967295 样本序号。
`OUTPUT_FAULT` 文本与上位机状态解析兼容。没有改变协议版本或虚构采样能力。

## 高云综合、布局布线

两种配置分别运行 `gw_sh.exe build.tcl`，环境变量 `HAPTICS_ARRAY=4x4/8x8`；
两者 `HAPTICS_PINOUT=j23`、`HAPTICS_DEVICE_VERSION=B`。
构建输入文件的 SHA-256（安全散列校验）均与工作树核对一致。

| 最差建立 / 保持余量 | +3.231 / +0.184 ns | +2.511 / +0.181 ns |
| 逻辑资源 | 12930 | 20451 |

| 物理端口与约束逐项相符 | 25 | 22 |
| 比特流生成 | 通过 | 通过 |

全部端口显式约束，无重复球位；4×4 为 16 路输出，8×8 为 12 条移位信号和四颗状态灯。
PR1014 通用时钟布线警告仍存在，时序报告未发现内部建立／保持违例。
外部 SN74LV595A 的布线延迟、时钟振铃和线缆影响不在当前内部时序结论内，仍须示波器确认。
OE 关闭是高阻态，R2 的驱动输入下拉不可省略；实际关断延迟也须测量。

## 接收采样后续更新

在本记录对应的 PR #17 数字修复基础上，后续加入了外置 ADCS7476 的 400 kS/s、12 位、200 点短窗口采样，包含预热转换、缓存保护、延迟 CAPTURE ACK、CRC 回传和电脑端来源兼容。PMOD0 分配为 SCLK=`T24`、CS_N=`R17`、SDATA=`L24`。本节是代码状态更新，不追溯修改上表的旧构建数字；以随后重新生成的综合报告为准。
