# 理论基准与双模式逐通道实测校准

日期：2026-10-22。对象：Tang MEGA 138K Pro、4×4 / 11 mm 阵列、40 kHz / 64 档相位。程序构建、仿真和界面自检不代表已完成实板声学验证。构建与界面脚本不自动烧录；用户另行授权后已完成示波器版 SRAM 临时下载及 COM7 状态回读，见验证记录。

## 1. 两个 FPGA 宏，独立于 MG24 通信宏

修改 [板级入口](rtl/board_top.v) 顶部后重新构建：

```verilog
`define FPGA_CALIBRATION_ENABLE 0
// 0：原有正常业务；1：上电关闭输出，等待校准工具
`define FPGA_CALIBRATION_SOURCE 0
// 0：示波器人工读数；1：ADC 自动采样，经电脑转发
```

FPGA（Field Programmable Gate Array，现场可编程门阵列）不区分 USB 或蓝牙。ADC（Analog-to-Digital Converter，模数转换器）在 MG24 上。两个 FPGA 宏都只接受 0/1；默认关闭校准，默认测量来源为示波器。

| FPGA 构建 | 开关 | 来源 | 使用方式 |
| --- | --- | --- | --- |
| `normal` | 0 | 0 | 原有控制程序，无校准等待 |
| `scope` | 1 | 0 | 今天使用：电脑＋示波器，不需要 MG24 |
| `adc` | 1 | 1 | MG24 到货后：USB／蓝牙采样，经电脑转发 |

MG24 自己仍用 `MG24_USE_BLUETOOTH`：0 自带 USB，1 低功耗蓝牙。已有代码和构建验证保留；不为人工模式修改或重新烧录 MG24。实际只烧录选定的通信版本，不需要额外 USB 转逻辑电平串口模块。蓝牙不代替接收板与 MG24 的供电，本轮没有蓝牙烧录功能。

## 2. 启动、构建及产物

直接双击 [start_calibration.cmd](../firmware/xiao_mg24/start_calibration.cmd) 打开中文窗口。打开后，在上方“连接与测点”区域第一行的“FPGA 串口”下拉框选择 **COM7**；没有显示时点旁边的“刷新串口”，也可以直接输入端口号。COM7 是本次实板使用的端口，换 USB 插口或电脑后需要重新核对。测量方式选择“示波器人工读数”，不需要填写 MG24 串口。确认摆放和接线后才点开始；打开窗口本身不会发射。

启动失败时控制台保留错误，不会立即消失；日志在 `.runtime/calibration/launcher/`。旧 `.ps1` 的中文编码与 Windows PowerShell 5.1 不兼容问题已修复。也可在已经打开的 PowerShell 中运行下面命令，查看完整报错。

在仓库根目录运行：

```powershell
# 现有环境已装依赖；新环境才需要安装
python -m pip install -r firmware/xiao_mg24/requirements.txt

# 独立中文窗口；不会自行连接、开始发射或烧录
powershell -NoProfile -ExecutionPolicy Bypass -File firmware/xiao_mg24/start_calibration.ps1

# 分别构建三种配置，不改变源码里的宏
python fpga/board/build_calibration.py --mode all
# 只构建今天需要的示波器版本
python fpga/board/build_calibration.py --mode scope
```

脚本默认使用 D 盘已安装的 Gowin；可以用 `--gowin` 指定 `gw_sh.exe`。目标为 GW5AST-LV138FPG676AC1/I0、器件版本 B；首次下载前核对真实器件版本、引脚及当前程序用途。

产物在 `.runtime/fpga-calibration/<模式>/calibration_<模式>/impl/pnr/board_top.fs`，日志在对应模式的 `build.log`，时序报告为 `board_top.tr`。需要手动使用现有下载工具选择正确板卡；本脚本没有下载动作。

## 3. 支架未齐时的临时摆放

```text
发射阵列竖直固定                 接收板固定
16 个换能器朝右   ── 100 mm ──   接收头朝左
阵列中心                        接收头前端中心
两者中心等高，声路中间没有手、夹具或线缆遮挡
```

1. 用稳固底座、现有夹具和绝缘垫固定板边，不能压元件或短接焊点。不要靠手持接收头完成整轮校准。
2. 以阵列前端面的中心为原点，左右为 X、上下为 Y、朝接收头为 Z。量的是发射换能器前端平面至接收头前端中心，不是两块电路板的距离。
3. 第一轮建议 `(0,0,100) mm`；这只是容易复现的起点，不是已验证的最佳距离。窗口必须填写实测坐标，偏心时填写实际 X/Y。
4. 两边线缆固定并留松弛量，不拉扯接收头。声路附近桌面、支架和其他物体位置保持不变；切换通道时不移动接收头。
5. 若无法可靠固定，先检查通道与削顶，不保存正式相位修正。约 343 m/s 的声速下，40 kHz 波长约 8.6 mm，毫米级移动已可能明显改变相位。

用户当前询问约 **7 cm** 的距离：可以作为待测点，程序允许 Z=70 mm；若接收头实际对准中心且量得 70 mm，窗口填 `(0,0,70) mm`，有偏心则填实际 X、Y。软件默认的 100 mm 没有自动修改。先检查该摆放下单路、双路的稳定性及削顶；改变距离、增益或等级后重新开始，不能直接沿用前半轮读数。此处只是允许的设置与操作方法，7 cm 的真实校准效果尚未测试。

旧 P4 支架的机械坐标不同于这个中心正前方布局，不能直接把其标注的离桌高度填入 Z；需要转换到阵列局部坐标。无需等支架补齐才检查波形。

## 4. 示波器接线与设置

- 接收板使用既有 **5 V** 电源，禁止接发射板的 12 V。保持原有分压、滤波和增益电路，不需要重画接收板。
- 探头尖端接接收板 `ADCV_P`，地夹接接收板 GND（Ground，地）。板资料中 U4 的 2 脚为输出，1/3/4 脚为地；上电前按实物核对。
- 普通接地示波器的地夹不能夹在换能器的驱动端。测驱动差分电压需按相应探头方法处理；今天校准只测接收输出。
- 接收板 SW1 先用低增益档，实物方向需核对。先以直流耦合检查偏置；时间轴可从 5～10 微秒/格开始，探头倍率和示波器设置一致，输入使用高阻档。
- 自动测量显示频率、峰峰值、最高值和最低值；调整电压档位使整个波形处于屏幕内。40 kHz 对应约 25 微秒一个周期。
- 名义 `ADCV_P` 静态中心约 0.485 V、理想上限约 0.97 V，这些是原电路标称计算值，必须核对实物。输出幅度小不能证明前级没削顶。

波峰/波谷切平时，先排除示波器量程问题，再确认低增益、降低发射等级；仍异常则依次检查 STAGE1、STAGE2、ADCV_P。细针状尖刺或振铃需要另行排查，不能直接当成削顶。若改变增益、等级、位置或探头测量节点，重新开始本轮。详见[接收板说明](../hardware/receiver/PCB调整建议.md)。

## 5. 今天的人工操作

1. 下载已核对的 `scope` 构建；连接电脑与 FPGA，关闭占用该串口的原控制程序。上电没有命令时输出关闭。
2. 打开中文窗口，选择 FPGA 串口、示波器模式、实测位置、等级和参考通道；默认等级 30，不等于 30% 声压。核对 16 路逻辑编号与接线后勾选摆放确认。
3. 点击开始。板端按这个测点计算理论相位，窗口显示理论基准。若固件来源宏不匹配，工具停止并提示。
4. 按当前提示读取峰峰值，以 **mV** 输入，确认波形稳定、近正弦且未削顶，再提交。背景步骤确认没有异常即可。每个条件重复三次，输入一项才推进一次；每项最多 120 秒。
5. 顺序为背景、参考单路，然后每个目标的单路、0°/90°/180°/270°附加相位、修正后两路复测。附加相位加在理论相位上，不是把理论相位替换成这四个数。参考通道修正固定为零。
6. 16 路完整流程为 92 个条件、276 次读数；从已有实测文件导入再复验为 32 个条件、96 次读数。初次可随时停止检查波形，停止后重新开始会从背景重测。
7. 取消、超时、失联或验证失败关闭输出。本轮候选表不覆盖已保存表。窗口有停止按钮；电脑保持心跳，用户无需在终端手工发送探活。
8. 全部通过后统一保存板内修正，回读核对，先保存电脑记录，再交还原有控制端点；输出仍然关闭。工具释放串口后再连接原控制程序。

原控制程序在已校准构建中若请求非 40 kHz／64 档，会收到 `CAL_REQUIRES_40K_64STEP`，配置被拒绝；输出另有不兼容配置的关闭门控。再次进入校准需要复位 FPGA；复位后可以重新测，或导入电脑文件复验。不能在板已进入正常控制后把校准二进制命令混入原控制串口。

## 6. MG24 到货后的自动模式

```text
接收板 ADCV_P ── MG24 A0/D0
接收板 GND    ── MG24 GND
MG24 自带 USB 或蓝牙 ── 电脑 ── 现有串口 ── FPGA
```

下载 `adc` 构建。窗口选 MG24 自带 USB 并指定另一个串口，或选蓝牙并填实际地址。扫描地址可用 `python firmware/xiao_mg24/receiver_client.py scan`。保持示波器检查接收前端；软件没有触轨提示不能证明前级线性。

工具先核对 MG24 身份和通信方式，获取新预检窗口；有效后才让 FPGA 开始。之后每个测量编号请求一个新窗口，记录原始 200 点及板端时间，转发 40 kHz 分量峰值的平方。电脑不求相位。断线不续用旧窗口或自动继续，重新连接后显式重新开始。

## 7. 理论、实测与文件

```text
理论相位 = 根据阵列与目标位置计算的聚焦相位
实测修正 = 这轮真实测量得到的逐通道误差补偿
最终相位 = (理论相位 + 实测修正) mod 64
```

此前 MCU（Microcontroller Unit，微控制器）的理论表只用于同一目标位置的计算对照；实测修正初始为零，不能再把理论相位加到理论相位上。

每轮自动创建 `.runtime/calibration/<时间>.jsonl` 过程记录；成功时同时创建 `.json` 校准文件，窗口可另存。包含理论基准、原始测量、来源、坐标、阵列、等级、参考通道、修正、板端启动标识和验证结果。没有将接收电压换算为绝对声压。

文件格式为 `schema=touchsee-fpga-calibration-1`、`kind=measured_phase_correction`、`simulated=false`。导入核对阵列、逻辑映射、位置、等级、参考通道、40 kHz／64 档及逐路范围；候选表仍需逐路单路和修正后双路复测，通过后才提交。理论表、演示文件和参数不匹配文件均拒绝。

示波器峰峰值按 `round((Vpp_mV/2 * 4095/3300)^2)` 转换为与 MG24 一致的名义原码平方尺度。只适用于高信噪比、近正弦、无失真的波形。人工背景只作为强弱门槛，不当作 40 kHz 频点功率扣除；自动模式使用频点背景。两者采用相同的四相位求解与修正后验证，保留各自原始指标以供追溯。

理想线性条件下，两路同相的幅值接近两路单独幅值之和；不同相位会使接收幅度变化，载波周期基本不变。原来已同相时提升可能很小。两路正常不代表全阵列不会饱和，正常播放前另外检查 16 路叠加时的量程。单点验证不能证明全空间声场或触觉图案已经校准。

## 8. 软件验证

```powershell
python -m unittest discover -s firmware/xiao_mg24/tests -p test_calibration.py -v
python firmware/xiao_mg24/tests/calibration_gui_smoke.py
python fpga/tb/run_tests.py --iverilog <iverilog.exe路径>
```

界面自检只使用合成端点，不打开真实串口；生成文件标记 `simulated=true`，不能导入实测。仿真覆盖全部 64 档、16 路及非零参考通道、候选表验证失败回滚、人工 120 秒、自动超时、相位表回读、输出和状态快照修正、串口校验和编号检查。原有测试仍需回归。

串口包及状态位的定义见 [CAL2 协议](CALIBRATION_PROTOCOL.md)。构建产物、时序、软件测试与硬件接入状态见 [2026-10-22 验证记录](VALIDATION_2026-10-22.md)。
