# FPGA 二维理论声场预览

> 2026-11-02：屏幕已到货，当前源码新增静态压力相位表及设备参数显示，详见[本次功能对齐](HOST_ALIGNMENT_2026-11-02.md)。下面保留首版实现与验证记录；旧位流摘要不代表当前源码。

本目录实现 Tang MEGA 138K Pro 的独立理论声场显示。FPGA（Field Programmable Gate Array，现场可编程门阵列）接收完整图形，在板内执行轨迹、求解相位、计算声场和生成画面。用户已选择先做二维和仅预览；触摸、实测接收和实际发射联动留待后续。

屏幕尚未到手。当前验证是代码仿真及高云工程检查，不是屏幕点亮、真实声场或触觉验证。构建程序不下载、不改动当前板上的双按键试验镜像。

## 图形到画面的链路

```text
完整图形参数 / 有序多段路径
    → 现有图形生成和轨迹插值
    → 锁存一个轨迹时刻及完整参数
    → 板内计算该时刻的64路相位
    → 计算64×64个空间位置的传播、衰减和相干叠加
    → 完整图像缓冲
    → 垂直消隐期切换显示图像
    → 颜色、坐标和状态文字
    → 视频输出
```

直线、圆形是测试用例，显示模块没有按图形类型写死声场。已有的点、直线、圆、方形、三角形、箭头及自定义多段路径走同一条链路。任意草图继续由电脑编辑器离散成有序路径，板端独立插值；第一版不在板内实现电脑编辑器的几何约束求解。

当前图形语义是单焦点沿轮廓运动。显示的是各轨迹时刻对应的稳态理论幅值分布，不是同时成形的完整轮廓，也不是40 kHz瞬时波形或传播瞬态仿真。运动速度超过声场画面更新能力时会发生时间欠采样；初次查看建议沿用每2秒一圈的慢速预览。

## 计算内容与边界

- 阵列：8×8，间距10.3 mm，理想等幅点声源；沿用当前行列坐标定义。
- 观察平面：与阵列平行，跟随图形高度；支持现有协议的20～300 mm高度、20～80 kHz载波及8～256档相位。
- 网格：64×64，间隔3 mm，采样点X/Y均为−94.5～+94.5 mm。预览构建声明焦点工作范围X/Y为±90 mm，越界图形由已有配置检查拒绝。
- 每点计算复数声压和的模：`|Σ exp(j(kr_i + phase_i)) / r_i|`；声速按343 m/s。八个并行计算单元逐行处理64个阵元。
- 颜色归一化参考为同一高度的`64/z`，保留各帧相对差异，不按每帧最大值重新缩放。改变高度时参考也随高度改变，不能用颜色跨高度比较绝对声压。
- 当前使用单位激励；没有电压到声压标定，驱动等级不被假定为线性声压比例。等级0/段间关闭呈现无激励状态，非零等级的热图显示单位激励空间分布。
- 没有加入换能器方向性、反射、逐通道实测误差、薄膜力学或包络响应。不输出Pa、作用力或触感强度。
- 当前为普通球面聚焦。窄焦斑专用整形表及实测修正表没有自动混入理想模型；以后接入实际输出相位时必须同时定义对应阵元误差模型。
- 正弦查找表和文字位图是常量。距离、倒数衰减、传播相位、复数累加、开方和归一化均由可综合逻辑计算；没有预存声场动画。

## 仅预览与操作

独立顶层为`theory_preview_top`。所有发射移位接口在板级固定关闭：数据/时钟/锁存为0、输出使能为禁用、清零为有效。`hap2_top`新增默认关闭的`PREVIEW_ONLY`参数；预览构建启用它，数组输出与状态中的实际`output`也始终为0。生产构建默认行为不变。

屏幕到货并完成点亮验证后，可用现有电脑程序下发图形、播放、暂停和停止；电脑不发送图像帧。远程控制保留现有心跳行为，失联后停止预览。

脱离电脑播放可使用已有本地模式：先下发完整配置、保持停止，切换`MODE value=LOCAL`，再用G15/S1播放/暂停。已有路径保留；F15/S2切换预设图形会重新生成路径。复位键K16返回停止。当前不新增触摸接口，也不自动把任意图形固化到掉电保存区。

## 视频与存储

- 目标屏为微雪7inch HDMI LCD (C)，1024×600。HDMI（High-Definition Multimedia Interface，高清多媒体接口）连接器上传输无音频的DVI（Digital Visual Interface，数字视频接口）兼容视频编码。
- 按厂家公开的EDID（Extended Display Identification Data，扩展显示识别数据）参考：像素时钟49 MHz；水平1024有效、48前肩、96同步、144后肩；垂直600有效、3前肩、10同步、11后肩。总周期1312×624，约59.85 Hz。当前暂用负同步极性，实际屏版本、极性兼容和点亮均待到货检查，未实现EDID读取或热插拔协商。
- 50 MHz板载时钟经PLL（Phase-Locked Loop，锁相环）产生49 MHz像素/计算时钟及245 MHz串行时钟，两个视频时钟保持5倍关系。主体控制、计算与图像缓冲均在像素时钟域。
- 每个串化器的复位由独立的像素域寄存器驱动，配置初值为复位有效；复位断言与释放均延后一拍。四个寄存器保留为独立单元供工具就近放置，避免复用大扇出复位网络或横跨输出接口的共享走线。两组视频时钟及复位恢复/移除时间完整分析，没有添加跨时钟假路径。
- 使用官方Pro例程的DVI0引脚：蓝AB24/AC24、绿V24/W24、红AA22/AA23、时钟Y22/Y23。以原理图网络和实际接口标记核对对应连接器，不套用旧60K板引脚。
- 视频采用TMDS（Transition-Minimized Differential Signaling，最小化传输差分信号）编码、OSER10串化和TLVDS差分输出缓冲。该缓冲及官方3.5 mA约束通过当前工具物理约束解析；不能替换成需要另一组电压条件的ELVDS缓冲。
- 声场双缓冲只占8192字节；像素颜色逐点生成，不存储两张1024×600彩色画面。静态文字另外使用单色只读位图。
- 图像、焦点标记和高度来自同一冻结快照；完成后只在垂直消隐期换前后台。停止或新配置立即使旧场无效，停止期间完成的旧计算不能在重新播放后恢复为有效图像。

## 构建与检查

在仓库根目录执行，Python环境需要NumPy和Pillow；默认使用本机微软雅黑字体生成中文文字位图。

```powershell
python fpga/preview/check_preview.py --part field --grid 64
python fpga/preview/check_preview.py --part integration
python fpga/preview/check_preview.py --part tmds
python fpga/preview/check_preview.py --part reset
python fpga/preview/check_preview.py --part video
python fpga/preview/check_preview.py --part animation
python fpga/preview/build_preview.py
```

`--part video`依赖先前数值检查产生的场数据，不与`--part field`同时运行。`--part animation`使用较小的48×48 mm中央观察区加快长序列仿真，间隔仍为3 mm；它不替代64×64全场检查。图形以完整的两段自定义路径通过模拟串口输入，相位与场值均在板内逻辑中生成。

构建和测试输出位于`.runtime/theory-preview/`；`build/manifest.json`仅在要求的构建及时序检查成功后产生，记录全部输入文件与产物校验值。缺少清单或来源校验不一致时不能把旧位流当作当前源码的构建结果。脚本不会调用下载器。

## 本轮验证记录

- 三组64×64完整场：中心70 mm/40 kHz/64档，偏心70 mm/40 kHz/64档，偏心100 mm/60 kHz/128档。与独立浮点点声源参考比较，最大绝对差异分别约1.19、1.25、1.38个8位颜色等级；检查每个像素地址、数量及无未知值。
- 每组完整场计算耗时2,035,818个时钟，按49 MHz为约41.55 ms；这是逻辑仿真周期数，不是实板计时。加上相位快照和整帧发布等待，预计连续显示约20幅新声场/秒；屏幕刷新约59.85 Hz。
- 自定义多段路径已验证配置接受、多个位置的场快照、暂停/继续/停止及全程实际阵列输出为0。
- 动态回放中的8个有效场快照另与独立、未量化的浮点聚焦参考比较，最大差异约3.32个8位颜色等级；这项检查贯穿串口图形输入、轨迹、板内相位计算及声场计算，包含相位量化误差。
- 2048个视频编码符号完成独立字节解码、控制码、直流平衡检查。
- 将复位驱动逻辑与本机高云OSER10官方仿真模型连接，验证复位初值、寄存延迟、重复复位，以及224组四路串化的位序、时钟对齐和连续字序；综合网表另核对各复位输出寄存器的配置初值为1。
- 视频仿真导出了完整1024×600画面，核对有效像素数量及无未知颜色；`tests/screen.png`来自视频逻辑的颜色输出，不是另写界面效果图。
- 原有8×8端到端仿真通过，串口采用1 Mbaud仿真副本加速；不声称本轮重跑了原115200波特率的整套长仿真。
- 2026-10-25 23:40最终物理构建通过：49 MHz像素/计算时钟的报告最高频率为51.348 MHz，当前约束下建立/保持违例均为0，恢复、移除及最小脉宽报告均无负余量。四路视频复位最小恢复余量0.568 ns、最小移除余量0.126 ns；没有跨时钟假路径。
- 245 MHz用于专用串化器，工具未报告该时钟的独立最高频率，不能把它说成一般逻辑已验证到245 MHz。保留工具关于板载输入`clk_d`使用通用路由的PR1014提示；视频链路、电气与屏幕兼容仍需实板验证。
- 已生成`build/preview/impl/pnr/theory_preview_top.fs`及`build/manifest.json`，核对位流、暂存输入和当前全部硬件源文件的校验值一致；综合网表中12个发射接口引脚均连接到预期关闭常量。位流SHA-256为`c591de7191882272ce415d1176f45b6a9195aafc0988e84222239af9755ccf5f`。尚未下载或连接屏幕。

### 资源与后续三维

资源占用应分别看逻辑、寄存器、存储器及专用乘加单元，不能把百分比相加。最终布局布线的占用可能高于综合估计，应以同一版位流的物理报告为准。

本轮最终布局布线报告如下，百分比沿用工具取整显示；包含当前完整预览工程，不包含后续触摸、实测采集或三维功能。

主要需要关注乘加资源和时序余量；不能根据逻辑单元只占17%就按剩余容量线性推算可增加的计算性能。详细资源与时序报告分别为`build/preview/impl/pnr/theory_preview_top.rpt.txt`和同目录`.tr`文件。

二维显示使用64×64个声场采样点，再放大绘制到512×512区域；1024×600是整个屏幕的像素数，不代表每帧计算614400个声场位置。两幅场值缓冲仅8192字节，但文字位图、正弦表和原有协议/路径存储也消耗片内存储资源。

后续“把二维幅值画成立体曲面”和“计算整个三维空间”是两类不同工作。若同样步进、逐点计算64×64×64个体素，单纯按采样点数外推就是二维的64倍，约2.66秒/体积，尚未包括三维绘制及存储开销。这只是当前架构的工作量估算，不是三维实现或性能承诺。应先明确展示方式，再选择切片、稀疏采样、复用运算或增加并行度。
